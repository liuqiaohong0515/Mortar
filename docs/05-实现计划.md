# 实现计划

本文只排顺序和技术选择。当前阶段不写功能代码。

规格以 [功能规格](02-功能规格.md) 和 [界面规格](03-界面规格.md) 为准。每一阶段结束时，用功能规格末尾的总清单勾选，没有勾上的不进入下一阶段的「完成」声明。

## 1. 技术选择

| 层 | 选择 | 原因 |
| --- | --- | --- |
| 界面壳 | SwiftUI 窗口、工具栏、偏好、表单 | 与现有工程一致，系统外观和深色模式成本低 |
| 列表与文本 | AppKit：`NSOutlineView`、`NSSplitView`、自绘差异视图 | 浏览器的列、拖放、万行滚动和并排差异用 SwiftUI List 达不到规格 |
| Subversion | 应用包内的 Subversion 1.14 命令行 | 与服务器、搁置、合并信息的行为一致，不必自研协议 |
| 旧工作副本 | 检测到 1.7 格式时只提示升级，确认后执行 `svn upgrade` | 1.14 客户端不直接使用 1.7 工作副本 |
| 缓存 | 应用支持目录中的 SQLite | 日志缓存、记录、源列表、会话 |
| 密码 | 钥匙串 | 与功能规格第 21 节一致 |
| 配置 | 默认读写 `~/.subversion` 和 `~/.ssh` | 非沙盒，其他 `svn` 客户端能共享认证和忽略规则 |

不把「再包一份 GUI 专用的 Subversion 库」放进第一期。命令行的进度解析足够做出记录视图。若某一操作的输出不够驱动界面（例如状态监视要每秒扫上万文件），再在那个阶段评估链接 `libsvn`，接口保持不变。

搁置必须走 `svn shelve` / `svn unshelve`，这样终端和其他 1.10+ 客户端能看见同一批搁置架。

## 2. 进程边界

所有 `svn` 调用经过同一个执行器：

- 每个工作副本同时只有一个写操作；读操作可以并行，但与写操作互斥
- 超时、取消、退出码、stdout、stderr 统一收进记录
- 认证失败时执行器暂停这一次调用，弹出一次对话框，再带上新的凭据重试
- 不把密码放进进程参数或日志。需要时通过 `--config-dir` 指向临时配置，或使用已配置的钥匙串集成
- 取消意味着杀掉该进程并接着 `svn cleanup`，避免工作队列锁残留

状态模型是应用内的一份快照，不让界面直接解析终端文本。执行器把 `svn status --xml`、`svn info --xml`、`svn log --xml` 转成模型后再刷新界面。

## 3. 阶段

阶段按依赖排列。后一阶段可以调用前一阶段的执行器和浏览器，不重复做仓库连接。

### 阶段 A — 壳

交付：主窗口三栏、工具栏五个分段、源列表空态、偏好六页的存取、会话恢复（窗口框、栏宽、检查器开关）。

不连接 Subversion。用假数据确认 [界面规格](03-界面规格.md) 的尺寸、过滤器条和深色模式。

完成标准：浅色和深色下主窗口与规格第 1–3 节一致，重启后栏宽还在。

### 阶段 B — 仓库与检出

对应总清单 2、3、4、5、6 的仓库侧。

- 添加与新建 FSFS 仓库
- HTTP、SVN、SSH 连接，指纹对话框，钥匙串
- 云预设只负责生成 URL
- 仓库浏览器：HEAD、历史修订、列、过滤、路径条
- 新建文件夹、删除、移动、Option 复制
- 导入、导出、下载
- 检出（修订、格式、深度、外部引用）并出现在源列表
- 拖入已有工作副本；1.7 只提示不静默升级

完成标准：能对着一个本地仓库和一个 `svn+ssh` 仓库完成导入和检出。记录视图先以纯文本显示命令输出。

### 阶段 C — 工作副本浏览器

对应总清单 1 的状态数字、7 的全部。

- `svn status` 快照、字母徽章、含有更改圆点
- 全部过滤器与 `⌘\`
- 添加、删除、还原、复制、移动、重命名
- 忽略、深度与排除单个文件
- 三个工具栏开关
- 双击行为与偏好
- 未提交数量

待更新数量放到阶段 D，因为它要访问仓库。

完成标准：对一份已有 Cornerstone 或命令行检出的工作副本，状态与 `svn status` 逐行一致。

### 阶段 D — 同步与提交

对应总清单 8 的更新/还原/清理/升级/修复，以及 14。

- 更新到最新、更新对话框
- 提交视图：日志草稿、最近日志、差异展开、成对路径、脚本
- 清理、升级、修复文件
- 切换、重新定位
- Dock 徽章
- 更新时按偏好切到记录，记录变成结构化条目

完成标准：一次提交产生的修订能在命令行 `svn log` 里看到相同的消息和路径。提交前脚本返回非零时修订号不变。

### 阶段 E — 比较与冲突

对应总清单 9、10、11。

- 并排文本差异、行内差异、空白与换行选项、不可见字符
- 修订弹出菜单
- WORKING 侧编辑和按块丢弃
- 语法高亮列表
- 图片三种模式
- 标注与图例
- 冲突四文件、解决菜单、外部合并工具
- 属性冲突和树冲突

完成标准：同一对文件在 Mortar 和 `svn diff` 中的增删行集合一致。一处文本冲突可以不借助终端解决并提交。

### 阶段 F — 历史

对应总清单 12 的入口可以先只做命令，视图在本阶段完成；总清单 15。

- 日志卡片、过滤器、更新和还原按钮、分享、复制
- 时间线符号、祖先展开、两修订比较
- SQLite 日志缓存与「缓存…」
- 问题跟踪链接（总清单 18）可以在本阶段一并做，因为链接只出现在日志文本里

完成标准：断网时已缓存的日志仍可浏览。时间线上的分支点修订号与 `svn log -v` 的复制来源一致。

### 阶段 G — 合并、标签、属性

对应总清单 12、13、17。

- 标签与分支建议路径
- 四种合并、检查清单、试运行、record-only
- 检查器全部段
- 属性编辑与单属性还原
- 外部引用编辑器
- 用户属性
- 锁：锁定、解锁、打破、窃取

完成标准：同步合并写入的 `svn:mergeinfo` 与对同一 URL 执行 `svn merge` 的结果一致。外部引用保存后能被命令行 `svn propget svn:externals` 读回。

### 阶段 H — 搁置与其余外壳

对应总清单 16、20、21、22 里尚未完成的项。

- 搁置与检查点，多版本，与 `svn shelve` 互通
- 通知中心
- 位置页（共享配置 / 私有配置）
- 全局忽略、自动属性
- 帮助入口与关于窗口中的 Subversion 版本
- 选择作用范围审计：把功能规格第 19 节的命令逐条点一遍

完成标准：Mortar 里创建的搁置架能用内嵌 `svn shelve list` 看到；取消搁置后工作副本状态与命令行 unshelve 相同。

## 4. 阶段之间不提前做的事

- 阶段 C 之前不做差异着色。没有稳定的状态模型时，差异视图会连错文件
- 阶段 D 之前不做待更新胶囊。它会在每次刷新时访问网络，拖慢浏览器调试
- 阶段 E 之前不接外部比较工具。左右文件顺序要以内置比较已经定下来的 BASE/WORKING/HEAD 为准
- 不并行做「自研合并算法」。合并只调用 `svn merge`

## 5. 每个阶段的检查方式

不引入新的测试框架要求，沿用工程能跑的方式：

1. 本地用 `svnadmin create` 做一个 FSFS 仓库，准备两份工作副本，模拟两人协作。
2. 对本阶段命令，对比 Mortar 结果和直接调用内嵌 `svn` 的 XML 输出。
3. 界面按 [界面规格](03-界面规格.md) 走一遍主路径：切换视图、过滤、检查器、浅色深色。
4. 把功能规格总清单里本阶段的项勾上，并在该阶段的提交说明里列出勾过的编号。

远程 `svn+ssh` 至少在阶段 B 和阶段 D 各做一次，避免认证只在 `file://` 下碰巧可用。

## 6. 风险

| 风险 | 处理 |
| --- | --- |
| `svn` 机器输出在补丁版本间变化 | 只解析 `--xml`。没有 XML 的子命令（shelve 的部分输出）单独做解析，并钉死内嵌的 1.14 次版本号 |
| 大工作副本全量 status 很慢 | 阶段 C 就做增量：文件监视触发受影响目录的 `svn status`，而不是每次重扫整个树 |
| 搁置在 1.14 仍标为实验特性 | 界面按规格做，关于窗口和搁置窗口写明依赖 Subversion shelve。不自研第二套搁置格式 |
| 云服务商登录接口已变化 | 预设只生成 URL 和用户名，认证走第 21 节的通用对话框 |
| 图片差异的像素模式在大图上耗内存 | 差异计算放后台，按可见区域取样；缩放时取消上一次计算 |
| 沙盒若将来要上架 | 位置页已经预留私有配置。启用沙盒时默认改为私有目录，脚本目录改到应用脚本目录。这是部署变化，不改变功能清单 |

## 7. 建议的第一段实现

阶段 A 和阶段 B 是第一条可演示的竖切：添加一个本地仓库，导入目录，检出，在源列表里看到工作副本。

在这条竖切完成并对照总清单 2–6 之前，不开始比较视图和合并视图。
