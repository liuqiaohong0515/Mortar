# 目标与范围

## 产品

Mortar 是给 macOS 用的原生 Subversion 客户端。用户用它管理仓库和工作副本：检出、更新、比较、提交、分支、合并、追溯历史。

对齐对象是 Cornerstone 4.2 对用户暴露的全部 Subversion 工作流。Cornerstone 的付费、许可证和商店不属于这个工作流。

当前工程是新建的 SwiftUI macOS App（`MortarApp.swift` / `ContentView.swift`）。本阶段只定规格，不改代码。

## 对齐标准

做到下面四点，才算一个功能「有」：

1. 用户能从对应的菜单、工具栏或上下文菜单到达该功能。
2. 选项与 Cornerstone 帮助书一致（深度、修订、忽略空白、外部引用、锁等）。
3. 结果与对同一工作副本执行相应 `svn` 子命令一致。
4. 界面落在 [界面规格](03-界面规格.md) 规定的视图里，而不是另做一套页面结构。

Subversion 命令行能做、但 Cornerstone 帮助书和发布说明都没做成界面的能力，不纳入首版必须项。例如：没有独立的 changelist 管理界面。官方帮助未把它列为功能。

## 版本与兼容

| 项 | 决定 |
| --- | --- |
| 对齐的产品版本 | Cornerstone 4.2 |
| 客户端 | 内嵌 Subversion 1.14（1.x 的长期支持版），覆盖 4.0 所用的 1.10 能力，包括 shelving |
| 工作副本格式 | 直接读写 1.8 及以上格式。打开 1.7 格式时提示升级；升级前不改动该工作副本 |
| 仓库格式 | 只创建和使用 FSFS。不创建、不打开 Berkeley DB 仓库（与 Cornerstone 相同，已确认） |
| 服务器 | 能连接仍提供 `http` / `https` / `svn` / `svn+ssh` / `file` 的 Subversion 服务器，含 1.7 及更新的服务器 |
| 系统 | 当前开发机所在的现代 macOS。界面同时支持浅色和深色（Cornerstone 4.2 已确认支持深色模式） |
| 沙盒 | 默认不启用 App Sandbox，以便直接使用 `~/.subversion` 和 `~/.ssh`。这对应非 Mac App Store 版 Cornerstone 的使用方式 |

Cornerstone 3 因为上架商店被迫沙盒化，因此出现了私有配置目录、脚本必须放进 Application Scripts、外部比较工具不能直接启动等限制。Mortar 不复制这些限制。比较工具、SSH 配置和提交脚本的**能力**全部保留，启动方式按非沙盒应用实现。详见功能规格中的「实现约定」。

## 仓库连接方式

必须全部提供：

- 本地 `file://` 仓库：添加已有仓库、新建仓库
- `http://` 与 `https://`
- `svn://` 与 `svn+ssh://`，含 SSH 隧道与 `SendEnv`（4.0 已确认）
- 从 Finder 把工作副本或仓库文件夹拖进源列表

云服务页保留为连接预设，而不是另一套版本控制：

- **Assembla**：提供 SVN 与 SVN+SSH 的地址和账号字段（4.0 已确认兼容 Assembla SVN+SSH）
- **Beanstalk、CloudForge、Codesion**：保留与当年 Cornerstone 相同的入口和 URL 模板。这些服务是否仍接受登录，取决于服务商；入口本身不能缺

## 明确不做

这些不属于「SVN 管理工具功能」：

- 许可证密钥、试用期、注销许可证、应用内购买
- 把 Assembla 账号体系、账单或代码托管控制台做进 Mortar
- 复制 Cornerstone 的名称、商标、应用图标和帮助书原文
- Git、Mercurial 或其他版本控制系统
- 在 iOS 或 Windows 上运行

界面对齐的是信息架构和交互（源列表、过滤器条、浏览器、比较、日志、时间线、记录、检查器），视觉使用 macOS 系统控件和 Mortar 自己的状态色，不描摹对方图标像素。

## 成功标准

一位每天使用 Cornerstone 4 的人，可以只靠 Mortar 完成同一套日常操作，并且不需要回到终端补做合并、shelve、外部引用、属性、锁或冲突处理。

验收时逐项勾 [功能规格](02-功能规格.md) 末尾的总清单。
