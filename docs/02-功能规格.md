# 功能规格

行为以 Cornerstone 帮助书为准。每节末尾的验收项是实现完成的判定条件。

术语与 Subversion 一致，界面文案使用下面这组中文（英文保留在括号里，便于对照 `svn`）：

| 术语 | 含义 |
| --- | --- |
| 仓库 | 中央版本库 |
| 工作副本 | 本机可编辑副本 |
| BASE / 上次更新 | 工作副本当前记录的修订 |
| WORKING / 工作版本 | 磁盘上尚未提交的内容 |
| HEAD / 仓库最新 | 仓库最新修订 |
| PREVIOUS / 前一修订 | 当前选中修订的上一修订 |
| 外部引用 | `svn:externals` |
| 搁置 / 检查点 | Cornerstone 4 的 Shelve 与 Checkpoint |

---

## 1. 源列表

源列表是整个应用的根。工作副本按所属仓库分组，仓库与工作副本在同一列表里（Cornerstone 3 已确认，不再分成两套列表）。

### 1.1 内容

- 分组标题为仓库昵称。其下是该仓库的工作副本。
- 仓库行显示昵称，副标题为主机名和路径。
- 工作副本行显示名称。名称默认取文件夹名，可在检查器或「显示简介」流程里辨认磁盘路径。
- 工作副本上显示两枚状态：
  - **未提交修改数量**（本地有改动）
  - **待更新数量**（仓库里有比 BASE 更新的修订）。这就是产品页上的 Pending Updates
- 无法访问的项（文件夹已删除、权限不足）用次要样式标出，并提供恢复：重新定位文件夹，或通过系统打开面板授权访问。
- 添加工作副本时，若源列表里还没有其仓库，自动加入该仓库。
- 从 Finder 拖入文件夹：是工作副本则加入工作副本，是 FSFS 仓库则加入仓库。

### 1.2 底部

- 「+」菜单：添加仓库、添加工作副本。进行中的操作把「+」换成活动指示器，两者占同一位置（Cornerstone 3 已确认）。
- 活动指示器可点开，转到对应的记录视图。

### 1.3 仓库上下文菜单

- 在 Finder 中显示（仅 `file://`）
- 新建文件夹、导入、检出
- 分支、标签
- 复制 URL
- 问题跟踪…
- 缓存…
- 从列表移除（不删除磁盘上的仓库）

### 1.4 工作副本上下文菜单

- 更新、更新…
- 提交、全部提交
- 还原…
- 清理
- 切换…
- 重新定位…
- 升级工作副本…
- 合并…
- 搁置…、取消搁置…
- 在 Finder 中显示、在终端中打开
- 从列表移除（不删除工作副本文件夹）

### 验收

- [ ] 工作副本按仓库分组，仓库行有主机和路径
- [ ] 拖入工作副本会自动补上仓库
- [ ] 未提交数与待更新数同时可见
- [ ] 失效路径有恢复入口，移除列表项不会删除磁盘文件

## 2. 添加与创建仓库

`文件 > 添加仓库…`，或源列表「+」。表单顶部用分段控件切换类型。

### 2.1 文件仓库

两种模式，用开关切换（已确认）：

**添加已有仓库**

- 选择仓库目录
- 昵称（不必等于目录名）

**新建仓库**

- 父目录（Where）
- 昵称
- 目录名（Create as）
- 兼容版本弹出菜单
- 只创建 FSFS
- 可选「创建标准目录」：`trunk`、`branches`、`tags`

兼容版本至少包含 1.8、1.9、1.10、1.14。新建仓库能被对应时代的 `svn` 客户端读取。

### 2.2 HTTP 服务器

- URL（`http` 或 `https`）
- 昵称
- 用户名（可空，表示匿名）
- 密码保存到钥匙串，可选择不保存

HTTPS 另见第 16 节证书。

### 2.3 SVN 服务器

- 主机、端口（默认 3690）、仓库路径
- 协议：`svn://` 或 `svn+ssh://`
- 用户名
- SSH：私钥、使用 ssh-agent、端口、`SendEnv`（形式为 `变量=值`，可多行）
- 自定义隧道：当用户改用 `~/.subversion` 配置时，尊重其中的 `tunnels` 定义

首次连接展示主机密钥指纹。算法覆盖 MD5 以及 SHA-256、SHA-384、SHA-512（Cornerstone 3 已确认）。用户可接受一次或永久写入 `known_hosts`。

### 2.4 云服务预设

每个预设收集账号和服务商要求的字段，最终仍生成上面的某种 URL：

| 预设 | 结果 |
| --- | --- |
| Assembla | `https` 或 `svn+ssh` 仓库 URL |
| Beanstalk / CloudForge / Codesion | 按该服务当年的仓库 URL 模板填写主机与路径 |

预设页在再次打开「添加仓库」时重置字段（3.0 发布说明里把「未重置」记为缺陷，说明这是预期行为）。

### 验收

- [ ] 五种入口都能把仓库放进源列表：文件、新建、HTTP、SVN/SSH、云预设
- [ ] 新建仓库是 FSFS，可选 trunk/branches/tags
- [ ] SSH 指纹使用 SHA-2，`SendEnv` 会进入隧道环境
- [ ] 密码进钥匙串，取消保存时不落盘

## 3. 仓库浏览器

选中源列表中的仓库后，主区为仓库浏览器。默认显示 HEAD。对本仓库的提交会自动刷新。`⌘R` 手动刷新。

### 3.1 列

- 名称
- 修订
- 作者
- 日期
- 大小
- 种类
- 锁状态

非 HEAD 修订下，会改写历史的操作不可用（移动、重命名、删除已有项）。复制到、新建文件夹、导入仍然可用，它们产生的是**新修订**，浏览器回到 HEAD 后才看得到（已确认）。

### 3.2 过滤器条

从左到右：

- 修订字段：HEAD，或修订号，或日期
- 分段：全部、最近修订、今天、本周、本月、已锁定
- 修订字段不是 HEAD 时，「最近修订」改为「此修订」
- 搜索框：名称、作者、修订号。停顿后自动过滤；回车把当前文本存入搜索历史
- `⌘\` 清除分段过滤和搜索文字
- 已锁定可与今天 / 本周 / 本月叠加
- 过滤只作用于已经加载到浏览器里的项，不为了过滤而拉取整个仓库（已确认）

### 3.3 导航

- 双击文件夹进入该文件夹，它成为当前根
- 路径条逐级回到上层
- 后退 / 前进走浏览器历史
- `⌘` 双击在 Finder 中显示（本地仓库）

### 3.4 修改仓库

这些操作都要求日志消息，并产生一个新修订：

| 操作 | 行为 |
| --- | --- |
| 新建文件夹 | 在当前目录创建 |
| 重命名 | 服务器端 rename |
| 移动 | 拖到目标文件夹 |
| 复制 | 按住 Option 拖放，弹出名称和源修订 |
| 删除 | 确认后删除 |
| 导入 | 见第 4 节 |
| 检出 | 见第 5 节 |
| 标签 / 分支 | 见第 12 节 |
| 下载 | 把选中项导出到「下载」文件夹，一键完成（Cornerstone 3 已确认） |
| 导出… | 选择目标位置的完整导出 |
| 锁定 / 解锁 | 文件锁，可填写注释；可打破他人的锁、可窃取锁 |
| 属性 | 通过检查器编辑，提交后成为新修订 |

从 Finder 拖入仓库浏览器即导入。按住 Option 放下时展示导入选项。导入永远是拷贝，不改动源文件（已确认）。

拖出浏览器到 Finder 执行导出。

### 验收

- [ ] 默认为 HEAD，可用修订号或日期浏览历史树
- [ ] 历史修订中不能移动或重命名，复制 / 新建 / 导入仍生成新修订
- [ ] 过滤器、路径条、后退前进与帮助书一致
- [ ] Option 拖放为复制并询问修订；普通拖放为移动
- [ ] 「下载」直接进入「下载」文件夹

## 4. 导入

入口：仓库浏览器工具栏、`文件 > 导入…`、文件夹上下文菜单、Finder 拖放。

1. 用系统打开面板选择文件或文件夹，可多选。
2. 只选中一项时，可用「导入为」改名。
3. 「包含子文件夹」默认打开。
4. 「按全局忽略规则跳过文件」默认打开。
5. 确认后进入日志消息步骤，再执行导入。
6. 成功后在该仓库的记录里留下这一修订。

导入不会把源目录变成工作副本。用户要编辑，必须再检出。

### 验收

- [ ] 多选、改名、不递归、忽略规则四个选项都生效
- [ ] 源文件保持原样
- [ ] 记录视图出现对应修订

---

## 5. 检出工作副本

入口：仓库浏览器选中文件夹后，`工作副本 > 检出工作副本…` 或工具栏「检出」。

字段：

- 存储为（目录名）
- 父目录
- 修订，默认 HEAD
- 工作副本格式
- 深度：完全、直接子项、仅文件、仅文件夹（对应 `infinity` / `immediates` / `files` / `empty`）
- 「检出外部引用的内容」，默认打开

完成后工作副本出现在源列表，并归到该仓库分组下。

若外部引用的 URL 不可达，操作以明确错误结束，并在记录里保留原因。

### 验收

- [ ] 修订、格式、深度、外部引用四个高级选项都传递给检出
- [ ] 新工作副本自动进入正确的仓库分组

---

## 6. 添加已有工作副本

`文件 > 添加工作副本…`，或拖入源列表。

- 选择包含 `.svn` 的目录
- 识别工作副本格式并选用匹配的客户端行为
- 1.7 格式：提示升级，用户确认前不改动
- 不受支持的更老格式：说明需要先用旧版 Subversion 升级，不写入该目录
- 嵌套在其他工作副本里的工作副本也可以单独加入（Cornerstone 3.0.1 把「不能加入」记为缺陷）

### 验收

- [ ] 拖入和菜单两条路径等价
- [ ] 1.7 与更老格式不会被静默改写

## 7. 工作副本浏览器

选中工作副本后显示。外观与 Finder 列表相近，并带版本控制状态。

### 7.1 刷新时机

自动刷新：

- 对本工作副本执行了操作
- 应用变为前台
- 仓库中对应项被锁定或解锁

手动刷新：`显示 > 刷新`（`⌘R`）。

### 7.2 列

默认可见：名称、工作副本状态、含有更改、修订、日期、大小。其余列由列菜单打开。

| 列 | 规则 |
| --- | --- |
| 名称 | 缺失或被忽略时用更浅的文字。忽略项和外部项使用斜体 |
| 工作副本状态 | 见下表。内容状态优先于属性状态。两者都要看时打开检查器 |
| 含有更改 | 仅对**折叠的**文件夹显示圆点，表示其中有未提交更改 |
| 仓库状态 | 仅当「显示仓库状态」打开时出现 |
| 修改日期 | 未改项用修订日期；已改项用文件系统日期 |
| 大小 | 文件大小 |
| 种类 | 文件类型描述 |
| 修订 | BASE 修订号 |
| 属性标记 | 存在 Subversion 属性时显示 |
| 锁 | 未锁定 / 本人持有 / 他人锁定 / 锁已失效 |
| 检出深度 | 完全 / 直接子项 / 仅文件 / 仅文件夹 |
| 作者 | BASE 修订作者。匿名提交可为空 |

工作副本状态字母与 `svn status` 一致：

| 字母 | 状态 | 含义 |
| --- | --- | --- |
| A | 已添加 | 含复制、移动、重命名后尚未提交的新路径 |
| C | 冲突 | 文本、属性或树冲突。未解决不能提交 |
| D | 已删除 | 含移动、重命名留下的旧路径 |
| X | 外部 | 由外部引用得到。能否展开由「显示外部引用内容」决定 |
| I | 已忽略 | 仅在「显示忽略项」打开时出现 |
| ! | 缺失 | 受版本控制但磁盘上不存在。还原可恢复，删除则从工作副本移除 |
| M | 已修改 | 文件内容已改 |
| ~ | 受阻 | 磁盘上的类型与版本库预期不符（文件 / 文件夹对调） |
| R | 已替换 | 删除后又添加，历史被打断 |
| S | 已切换 | 该项指向工作副本根以外的 URL |
| ? | 未版本控制 | 尚未 `svn add` |

属性状态在内容正常时单独显示：属性添加、属性冲突、属性删除、属性修改、属性替换。

### 7.3 过滤器条

分段（已确认，控制键为浏览器快捷键）：

| 分段 | 快捷键 | 范围 |
| --- | --- | --- |
| 全部 | ⌃A | 恢复过滤前的展开状态 |
| 已更改 | ⌃C | 添加、冲突、删除、缺失、修改、受阻、替换、未版本控制。不含外部和忽略 |
| 已修改 | ⌃O | 内容或属性已修改 |
| 冲突 | ⌃F | 含属性冲突 |
| 缺失 | ⌃G | 受版本控制但文件不在 |
| 未版本控制 | ⌃U | |
| 已切换 | ⌃S | |
| 已锁定 | ⌃L | 可与已更改、已修改、冲突、未版本控制、仓库有更新叠加 |
| 仓库有更新 | ⌃N | 仅当「显示仓库状态」打开。HEAD 高于 BASE |

搜索框匹配名称、作者、修订号，规则与仓库浏览器相同。`⌘\` 同时清除分段和搜索。点「全部」只清除分段，不清除搜索。

上下文菜单「在全部项中显示」会关掉过滤并滚到该项。

### 7.4 导航与打开

- 双击文件夹：进入该文件夹
- 双击包（`.nib`、`.pages` 等）：用默认应用打开；按住 Option 双击则进入浏览
- `⌘` 双击文件夹：在 Finder 中打开；`⌘` 双击文件：在 Finder 中显示
- 双击文件：按偏好决定（外部编辑器 / 与 BASE 比较 / 快速查看），默认外部编辑器
- 路径条、后退、前进与仓库浏览器相同
- 检查器「打开方式」可指定该类型的编辑器，「全部更改…」把该选择写成此类型的默认应用

### 7.5 工具栏开关

与菜单同一状态：

- 显示忽略项（`显示 > 显示忽略项`）
- 显示外部引用内容（`显示 > 显示外部引用内容`）
- 显示仓库状态（`显示 > 显示仓库状态`）

打开「显示仓库状态」后，每次刷新、提交、更新都会访问仓库。大工作副本上这是预期的性能代价，需要在界面上保持可关闭。

### 7.6 文件操作

全部通过 Subversion 完成，不用 Finder 语义直接改名：

| 操作 | 行为 |
| --- | --- |
| 添加 | 未版本控制项。文件夹默认递归 |
| 删除 | 版本控制项变为已删除。可选择同时移到废纸篓 |
| 还原 | 回到 BASE。缺失项会被找回。已添加项取消添加 |
| 复制 | 工作副本内 `svn copy` |
| 移动 / 重命名 | `svn move`。提交时新旧路径必须一起提交（1.8 及以上格式，Cornerstone 3 已确认） |
| 忽略 | 仅未版本控制项。把名字写入父目录 `svn:ignore`。大小写敏感 |
| 锁定 / 解锁 | 同仓库浏览器。`svn:needs-lock` 的文件在解锁时为只读 |
| 设置深度 | 排除文件夹或单个文件（深度改为 empty），或把目录更新到更深的深度 |
| 比较 | 见第 9 节 |
| 快速查看 | 系统 Quick Look |
| 在终端中打开 | 新的「终端」窗口，工作目录为该项所在目录 |
| 保存补丁 | 把选中范围的 `svn diff` 存成文件 |

移动和重命名在提交列表里成对勾选：勾上或取消其中一个，另一个跟随。

### 验收

- [ ] 状态字母与 `svn status` 一致，内容状态压过属性状态
- [ ] 含有更改的圆点只出现在折叠文件夹上
- [ ] 九个过滤器及叠加规则与帮助书一致
- [ ] 包、Finder、编辑器三种双击行为可区分
- [ ] 重命名产生的添加和删除不能被拆开提交
- [ ] 可以排除单个文件（稀疏工作副本）

## 8. 更新、还原、切换、重新定位、清理、升级

### 8.1 更新

- `更新到最新修订`：使用检查器里「更新时包含外部引用」的默认值
- `更新…`（`⇧⌘U`）：可选目标修订、深度、是否更新外部引用
- 日志视图每条修订提供「更新到此修订」
- 更新进行时按偏好切换到记录视图（默认打开）
- 选择范围遵循第 19 节

### 8.2 还原

- `还原…` 确认对话框列出将丢失的本地修改
- 可还原选中项或整棵子树
- 日志视图中，比当前项更旧的修订提供「还原到此修订」
- 工作副本有未提交修改时，先询问保留还是丢弃这些修改
- 检查器里单个属性可以单独还原到 BASE，再保存

### 8.3 切换

把工作副本（通常是根）切到同一仓库的另一 URL，例如从 `trunk` 到某个分支。

选项：目标 URL、修订、深度。有未提交修改时警告冲突风险。

`切换…` 放在源列表工作副本菜单。浏览器上下文菜单不放这项（Cornerstone 3 已从浏览器菜单移除，保留在源列表）。

### 8.4 重新定位

仓库根 URL 变了（换主机、换协议、换路径前缀）时改写工作副本元数据，不改文件内容。

若用户改的是目录分量，相关工作副本一并询问是否跟着改。目标 URL 不是同一仓库时给出「无效的重新定位目标」。

### 8.5 清理

`svn cleanup`：清除工作队列锁、完成被中断的操作。不删除未版本控制文件。

### 8.6 升级工作副本

把 1.7（以及应用能识别的旧格式）升级到内嵌客户端使用的格式。对话框说明升级后旧客户端可能无法再写这个工作副本，并提供继续与取消。

没有「降级工作副本」。Subversion 1.8 之后不能降级。

### 8.7 修复文件

针对「只把新名字加进版本库、旧路径仍留在版本库」的不一致。检测到成对的添加和应删除旧路径时，提供修复：把旧路径安排为删除，使一次提交同时完成改名。

### 验收

- [ ] 更新对话框能关外部引用、选修订和深度
- [ ] 日志里的更新与还原按钮行为与帮助书一致
- [ ] 切换与重新定位是两个不同命令
- [ ] 清理不删除未版本控制文件
- [ ] 升级有明确警告；没有降级命令
- [ ] 修复文件能补上改名留下的删除

## 9. 比较

内置比较是主路径。外部工具是补充。

### 9.1 入口

| 动作 | 快捷键 | 结果 |
| --- | --- | --- |
| 与 BASE 比较 | `⌘↩` | 左 BASE，右 WORKING |
| 与 HEAD 比较 | 工具栏 | 左 WORKING，右 HEAD |
| 在比较视图里改左侧为 BASE | 修订弹出菜单 | BASE 对 HEAD |
| 日志中双击某文件 | `⌘↩` | 该修订相对前一修订 |
| 时间线选两个修订 | `⌘` 点第二点 | 较早者在左 |
| 记录里的传入变更 | 显示差异 | 传入修订对更新前的本地修订，忽略未提交修改 |

文本文件打开后滚到第一处差异并选中。

比较视图按 Escape 回到进入之前的视图。

修订弹出菜单始终提供 BASE、WORKING、HEAD、PREVIOUS，以及修订号和日期。文件夹不能做内容比较。

### 9.2 文本比较

左右并排，同步滚动。

- 行内差异默认打开
- 行号默认打开
- 空白差异：打开时逐字符比较；关闭时把连续空格和 Tab 折成一个空格。不影响换行
- 换行差异：关闭时忽略 LF 与 CRLF 的差别
- 不可见字符默认关闭。空格、Tab、换行、分页符用与 BBEdit 同类的字形：换行用 ¬，分页用 ¶
- 语法高亮，语言见 9.5
- 上一个 / 下一个差异：`⌘↑` / `⌘↓`
- 滚动条上的差异标记；上一个 / 下一个按钮。按住 Option 跳到第一处或最后一处
- 选择：双击单词、三击整行、四击整个差异块
- `⌘A` 选择左侧全部，`⌥⌘A` 选择右侧全部

右侧为 WORKING 时：

- 可以直接编辑工作文件
- 每个差异块可以把左侧内容应用到右侧，或丢弃右侧这一处修改
- 编辑进入工作副本，状态保持为已修改，直到提交或还原

### 9.3 图片比较

对常见位图（PNG、JPEG、GIF、TIFF、BMP）使用图片视图，不走文本差异：

- 并排，同步滚动和缩放
- 滑动擦除：同一画布上拖动分割线
- 像素差异：不同的像素用状态色标出
- 适应窗口、实际像素、缩放比例

Cornerstone 产品页把图片比较列为内置能力；帮助书的比较章节主要描述文本。以上四种呈现是 Mortar 必须交付的图片比较，用来覆盖「不用离开应用就能看图片差异」。

### 9.4 其他文件

- 二进制且非图片：说明两侧都是二进制，给出大小和校验和，并提供外部工具
- 仅属性变化：以文本显示属性名与新旧值
- PDF、Word 等：能用已配置的外部工具打开时走外部工具，否则按二进制处理

### 9.5 语法高亮

至少覆盖 Cornerstone 3 已支持的语言：C、C++、Objective-C、C#、Java、JavaScript、JSON、Python、Ruby、Perl、PHP、HTML、CSS、XML、SQL、Oracle PL/SQL（`.pks`、`.pkb`）、Shell、Swift。

另加实现成本低且仓库里常见的类型：Markdown、YAML、Go、Rust、Swift 已含。高亮失败时退回纯文本，比较仍然可用。

字体用偏好里的等宽字体，默认跟随系统等宽字体（通常是 Menlo），并遵守「字体平滑」和 Tab 宽度。

### 9.6 外部比较工具

偏好中选择外部比较工具和外部合并工具。

比较工具清单（与帮助书一致，装了哪个用哪个）：

Apple 文件合并、Araxis Merge、BBEdit、TextWrangler、Kaleidoscope、Changes、DeltaWalker、TextMate、Microsoft Word、P4Merge、DiffMerge，以及自定义脚本。

调用约定（已确认）：

- BASE 对 WORKING：BASE 为旧文件且只读，WORKING 为新文件
- WORKING 对 HEAD：WORKING 为旧文件，HEAD 为新文件且只读
- 时间线上已选两个修订：`文件 > 使用…比较 > 比较所选修订`（`⇧⌘C`）
- 按住 Option 再点「与 BASE 比较」走外部工具（`⇧⌘B`）
- 按住 Option 再点「与 HEAD 比较」走外部工具（`⇧⌘H`）

非沙盒实现约定：检测到已安装的应用后直接启动，不必先把插件拖进脚本目录。自定义脚本仍然可用。

### 验收

- [ ] BASE、HEAD、PREVIOUS、修订号、日期都能作为任一侧
- [ ] 空白、换行、行内差异、行号、不可见字符、标注都可独立开关
- [ ] WORKING 一侧能编辑，并能按差异块丢弃
- [ ] 图片有并排、擦除、像素差异和缩放
- [ ] 外部工具的左右顺序与帮助书一致

## 10. 标注

- 点击其他修订或点击修订以外的正文，取消激活

### 图例窗口

- 每位作者一种颜色
- 点击作者，只高亮该作者的行
- 显示该作者在本文件中的行数或占比

## 11. 冲突

冲突来自更新或合并。冲突项不能提交。

### 11.1 文本冲突

工作文件里保留 Subversion 冲突标记（`<<<<<<<`、`=======`、`>>>>>>>`）。

选中冲突文件时，工具栏提供：

- 与「我的版本」（`.mine`）比较
- 与 HEAD 比较
- 与 BASE 比较
- 打开按钮的菜单：HEAD、BASE、`.mine`、已合并的工作文件
- 解决（`⌘K`）
- 按住「解决」弹出：解决为 HEAD、BASE、我的版本或当前工作文件

冲突条放在浏览器或比较视图顶部，右侧选择要采用的版本。

手工改完标记后，执行「解决冲突」把状态从冲突改为已修改。

### 11.2 外部合并工具

`工作副本 > 使用工具解决冲突`。工具清单：文件合并、Araxis Merge、DeltaWalker、P4Merge、DiffMerge。

四个文件：

| 角色 | 内容 |
| --- | --- |
| 我的修改 | 冲突前的未提交内容，作为原始侧 |
| 仓库最新 | 冲突发生时的 HEAD，作为修改侧 |
| 上次更新 | 冲突前的 BASE，作为共同祖先 |
| 工作版本 | 带标记的文件，工具保存到这里 |

保存后回到 Mortar，再执行「解决冲突」。

### 11.3 属性冲突与树冲突

- 属性冲突在检查器状态区单独显示，解决时选择保留本地属性、采用仓库属性，或手工编辑后标记解决
- 树冲突在检查器「树」一行显示，并在浏览器里用冲突状态标出
- 树冲突提供明确动作，而不是只显示错误：采用传入变更、保留本地状态。动作对应 `svn resolve --accept` 的相应取值
- 有树冲突的文件夹，状态提示说明这是树冲突

### 验收

- [ ] 未解决的冲突无法被勾进一次成功的提交
- [ ] 四种版本都能打开和比较
- [ ] 外部工具按四文件约定启动，结果写回工作文件
- [ ] 属性冲突和树冲突有各自的解决动作

## 12. 标签与分支

标签和分支都是服务器端复制。另外提供专用命令，在符合惯例的仓库里少填路径。

惯例目录：`trunk`、`branches`、`tags`，可选 `vendor`。不强制这种结构。

### 12.1 标签…

选中仓库中的文件夹：

- 标签名称
- 位置：选中项在 `trunk` 或 `branches` 下时，自动建议对应的 `tags` 目录。可改。接受相对 URL，默认显示为仓库相对路径
- 修订，默认 HEAD
- 日志消息

### 12.2 分支…

与标签相同。选中项在 `trunk` 或 `tags` 下时，建议对应的 `branches` 目录。

### 12.3 用复制完成

Option 拖到目标文件夹，填写名称和源修订。标签和分支之后可以像普通文件夹一样重命名和删除。

### 验收

- [ ] 标签和分支都会建议符合惯例的目标目录，并允许改掉
- [ ] 复制拖放能指定源修订
- [ ] 非标准目录结构下仍可手工指定 URL

## 13. 合并

合并的目标永远是一个工作副本。入口：选中工作副本或其子目录，`工作副本 > 合并…` 或工具栏「合并」。

四种策略做成同一视图里的四个选择：

### 13.1 同步分支

把某分支自上次合并以来的变更同步进当前工作副本。典型用途：功能分支跟上 `trunk`。

### 13.2 重新集成

把功能分支合并回其来源（通常是 `trunk` 的工作副本）。

此策略不提供深度和「忽略历史」选项（已确认）。

### 13.3 拣选

从源 URL 勾选一个或多个修订（或修订范围），合并进当前工作副本。修订列表默认不全部勾选。

### 13.4 高级

比较任意两个 URL（可以没有共同祖先），把差异合并进当前工作副本。

- 比较路径 + 修订，默认 HEAD
- 对照路径 + 修订，默认 HEAD

### 13.5 公共选项

- 深度，默认「包含所有层级」。重新集成时不显示
- 忽略空白、忽略换行，默认都不忽略
- 忽略历史，默认关闭。重新集成时不显示
- 只记录合并信息（`record-only`）放在选项弹出菜单里，供已经在别处合并过、只需补 `svn:mergeinfo` 的情况使用

### 13.6 工作副本检查与预览

执行前检查并在视图中列出：

- 有未提交修改：警告，并提供「还原…」「提交…」
- 不是最新：警告，并提供「更新到最新修订」

检查通过后显示变更预览（试运行）。预览和真正的合并都写入记录，并带修订范围。

合并结果留在工作副本里，不自动提交。用户按第 9、11 节复核和解决冲突后再提交。

### 验收

- [ ] 四种策略的入口和禁用项与帮助书一致
- [ ] 拣选可以勾选不相邻的修订
- [ ] 试运行预览先于真正写入
- [ ] 合并本身不产生提交

## 14. 提交

`工作副本 > 提交` 打开提交视图。在日志字段外，`⌘T` 执行提交。`⌥⌘T` 为「提交全部更改」，忽略当前选择。

提交视图占用主内容区，左右并排：

**左侧**

- 日志消息。回车换行，不关闭视图
- 「最近的日志」弹出该仓库近期日志，选一条填入
- 拼写默认不自动纠正；语法和拼写的开关记入偏好
- 日志文字字号可在偏好里单独设置
- 取消（Escape）不提交。已经写过的日志留到下一次提交

**右侧**

- 变更列表，默认全选
- 复选框排除文件。排除文件夹默认不递归；按住 Option 点击则递归
- 移动 / 重命名产生的一对路径联动勾选
- 行尾箭头展开该文件相对 BASE 的内置差异
- 空目录不显示展开按钮

**选项**

- 提交后解除锁
- 提交前脚本
- 提交后脚本

脚本支持 `.sh`、`.pl`、`.py`、`.scpt`、`.workflow`。目录默认为 `~/Library/Application Support/Mortar/Scripts`，选择器里有「打开脚本文件夹」。

传给脚本的信息：工作副本路径、仓库 URL、日志文件路径、本次包含的路径列表。提交后脚本额外得到新修订号。

提交前脚本以非零退出则中止提交，工作副本保持原样。提交后脚本失败不影响已经成功的修订，失败写入记录。

没有任何可提交更改时，提交按钮不可用。存在未解决冲突时，提交被拒绝并说明哪些路径。

### 验收

- [ ] 日志和差异并排，取消会保留草稿
- [ ] Option 点击文件夹复选框才递归
- [ ] 成对的移动路径联动
- [ ] 提交前脚本失败不会产生修订
- [ ] `⌥⌘T` 忽略选择，提交整个工作副本的更改

## 15. 日志、时间线、记录

历史有两种视图。记录是操作流水，不是仓库历史。

### 15.1 日志

自上而下，新修订在上，风格接近 `svn log`。

每条包含：修订号、作者、日期、日志消息、变更列表。变更默认折叠，按添加、删除、修改、替换分组。

- 工作副本的 BASE 修订带「工作副本」角标
- 双击变更中的文件打开比较
- 更新到此修订、还原到此修订（还原按钮出现在比当前修订更旧的条目上）
- 系统分享菜单分享该条日志
- 问题编号按第 18 节变成链接
- 复制按钮复制该条日志的修订、作者、日期和消息

过滤器：

| 分段 | 快捷键 | 说明 |
| --- | --- | --- |
| 全部 | ⌃A | |
| 我的更改 | ⌃Y | 当前仓库用户名；`file://` 用系统用户名。没有用户名时不显示 |
| 他人的更改 | ⌃P | 同上 |
| 更新的 | ⌃N | 新于所选工作副本项的 BASE。仅工作副本上下文 |
| 今天 | ⌃T | |
| 本周 | ⌃W | |
| 本月 | ⌃M | |
| 含添加 | ⌃E | 变更集里有添加或复制 |
| 含删除 | ⌃D | |
| 含替换 | ⌃R | |

搜索匹配日志消息、作者、路径。

### 15.2 时间线

一条水平条表示一个路径，左旧右新。多选时上下堆叠，用来对照多个文件的历史。

修订符号：

| 符号 | 含义 |
| --- | --- |
| 添加 | 导入或添加到版本库 |
| 分支 | 复制、移动、重命名。可展开祖先，标出分支点修订 |
| 修改 | 内容或属性修改 |
| 路径上有变更 | 该项本身没变：祖先被分支或修改，或（文件夹）子孙增删改 |
| 删除 | 该项被删除 |

- 轴默认只显示修订号，展开后显示日期等信息
- 点一个修订，再 `⌘` 点另一个，下方比较，较早者在左
- 文件夹不能比较内容
- 外部工具比较所选修订：`⇧⌘C`
- 检查器显示当前修订的作者、日期、消息、变更集
- 过滤能力多于日志：按作者、日期范围、修订范围缩小条上的点

### 15.3 日志缓存

每个仓库一份本地缓存。源列表仓库菜单「缓存…」：

- 开关
- 占用空间
- 清除缓存
- 缓存不完整时，日志和时间线继续向服务器补页，补到的内容写入缓存

### 15.4 记录

记录每次导入、检出、更新、提交、合并（含试运行）的进度和结果。

- 条目追加时自动展开
- 更新类结果用颜色区分添加、删除、更新、合并、冲突
- 文本、属性、锁图标有工具提示
- 合并条目显示修订范围
- 「显示差异」：传入修订对更新前版本
- 「在工作副本中显示」
- 「添加笔记」：给某条记录写本地备注，不进仓库
- 保留策略：被新条目替换时丢弃、15 分钟、1 小时、1 天、1 周、1 个月
- 偏好「更新工作副本时显示记录」，默认打开

记录按工作副本和仓库分开。切换源列表选择即切换记录。

### 验收

- [ ] 日志分组动作、角标、更新和还原按钮齐全
- [ ] 时间线符号五种都可区分，分支可展开到祖先
- [ ] 时间线 `⌘` 点两修订能比较
- [ ] 缓存可关闭、可清空，且不会挡住继续向服务器取日志
- [ ] 记录含试运行合并和用户笔记

## 16. 搁置与检查点

Cornerstone 4.0 的能力，对应 Subversion 1.10 及以上的 shelve。只对工作副本，不对仓库浏览器。

差异：

| | 搁置 | 检查点 |
| --- | --- | --- |
| 保存内容 | 当前未提交修改 | 当前未提交修改 |
| 之后的工作副本 | 这些修改被还原 | 修改留在工作副本里 |

### 16.1 搁置窗口

入口：`工作副本` 菜单、源列表上下文菜单，或在浏览器里对已修改 / 已添加 / 已删除的文件执行「搁置更改…」。

- 分段：搁置并还原 / 保存检查点（不还原）
- 新建搁置架并命名，或追加到已有搁置架（成为新版本）
- 日志可选。同一搁置架各版本共用一条日志
- 文件列表可多选，带全选。从浏览器进入时，当前选择已勾上
- 目录和二进制文件不能单独搁置，对应菜单项不可用
- 二进制文件的搁置在 4.1 已支持：当选择包含二进制且用户搁置的是「整个变更集」而不是「对图片执行文本搁置」时允许。单选一张图片时命令不可用（与帮助书「不能对图片或目录使用」一致）；在搁置窗口的文件列表里可以带上二进制文件

### 16.2 取消搁置窗口

- 左侧搁置架列表
- 中间该架的版本
- 右侧该版本的文件
- 「应用搁置的更改」把所选版本打回工作副本
- 没有任何搁置架时，应用按钮不可用

搁置数据存放在工作副本的 Subversion 元数据中，与 `svn shelve` / `svn unshelve` 互通。

### 验收

- [ ] 搁置会还原工作副本，检查点不会
- [ ] 同一搁置架可以有多个版本
- [ ] 单选图片或目录时，浏览器里的搁置命令不可用
- [ ] 取消搁置把所选版本应用到工作副本

## 17. 检查器、属性、外部引用、锁

`显示 > 显示检查器`（`⌘I`）或工具栏按钮。右侧栏，各段可折叠。多选时名称变为个数，大小变为合计。空段隐藏，不放占位文案。

### 17.1 通用

名称、大小、修订、位置（家目录内写成 `~` 开头）、修改日期、提交日期、作者、深度。

未版本控制项不显示修订、提交日期。文件夹不显示单个文件大小（多选除外，显示合计）。

### 17.2 状态

文本、属性、树、已切换。没有异常就不显示该行。

### 17.3 工作副本

只在选中工作副本根，或选中的项能确定所属工作副本时显示：

- 格式（检出时的工作副本格式）
- 「默认更新外部引用内容」。作用于「更新到最新」，并作为「更新…」对话框的默认值

### 17.4 仓库

仓库 URL、仓库中的名称、仓库中的路径。

若 BASE 不是 HEAD，并且打开了仓库状态，再显示仓库侧的文本状态、属性状态、修订、日期、作者。与工作副本相同时这些行隐藏。

### 17.5 锁

状态：未锁定、他人锁定、本人持有、已失效、已被窃取。

未锁定时不展示其余字段。其余字段：创建时间、过期时间、注释。过期时间留给服务器将来的能力，客户端不提供设置过期（与 1.8 时代的 Cornerstone 说明一致）。

### 17.6 属性

同一类型（都是文件，或都是文件夹）才能一起编辑。

文件：

| 字段 | 属性 | 编辑方式 |
| --- | --- | --- |
| 关键字 | `svn:keywords` | 词元输入，自动补全。菜单插入 `Date` `Revision` `Author` `HeadURL` `Id` `Header` |
| 换行 | `svn:eol-style` | 不处理 / 转换为系统 / LF / CR / CRLF |
| MIME | `svn:mime-type` | 常用列表，也可直接输入 |
| 可执行 | `svn:executable` | 是 / 否。添加可执行文件时自动为「是」 |
| 需要锁定 | `svn:needs-lock` | 是 / 否。为「是」时工作副本中该文件只读，锁定后可写 |

文件夹：

| 字段 | 属性 | 编辑方式 |
| --- | --- | --- |
| 忽略 | `svn:ignore` | 词元。支持 `*` 和 `?`，大小写敏感，不向下继承 |
| 外部引用 | `svn:externals` | 只读表格 + 「编辑外部引用」（`⇧⌘X`） |

已修改的属性在行上显示标记。悬停变成按钮，菜单「还原到上次更新」。改完要点「保存更改」才写回工作副本。

忽略的限制：已受版本控制的项不能直接忽略。若它正被添加，先还原再忽略。全局忽略在偏好里设置。

### 17.7 用户属性

由偏好定义，所有仓库共用一套字段，不按文件类型或路径分套。类型：文本、复选框、弹出列表、文件（文件内容存进属性值）。

### 17.8 外部引用编辑器

表格列顺序与属性文本一致：`来源[@修订] 本地路径`。

- 修订默认写 peg 修订（来源 URL 后的 `@`）
- 展开后才分别填写 operative 修订和 peg 修订
- 本地路径为空时，根据 URL 最后一段建议目录名
- 修订留空（即将来按 HEAD 解释）时提示。偏好可关闭这则提示
- URL 里带用户名时提示去掉。偏好可关闭这则提示
- 使用 peg 时写成 Subversion 1.5 及以后的格式
- 提供原始文本模式，供需要写成 1.4 风格（只有 operative 修订）的仓库

### 17.9 打开方式

选择外部编辑器。「全部更改…」应用到同一类型。

### 验收

- [ ] 检查器单页包含上述各段，空段隐藏
- [ ] 多选显示个数和总大小
- [ ] 关键字和忽略是词元而不是裸文本框
- [ ] 单个属性可还原
- [ ] 外部引用编辑器默认写 peg，并能展开 operative
- [ ] 用户属性四种类型都能读写

## 18. 问题跟踪

按仓库配置，入口在仓库上下文菜单「问题跟踪…」。

每条规则：

- 编号样式：预置 `#数字`、`[数字]` 等，或自定义正则
- URL 模板：预置样式用 `{number}`；自定义正则用 `{0}` 表示整段匹配，`{1}`… 表示分组，`{名字}` 表示命名分组

一个仓库可以有多条规则，用于格式变迁或同时使用多套系统。

日志消息、提交视图里的历史日志、时间线检查器中的消息，匹配到的编号显示为链接，在浏览器中打开。

### 验收

- [ ] 规则按仓库保存
- [ ] 预置样式和正则分组都能生成正确 URL
- [ ] 日志中的编号可点击

## 19. 选择决定作用范围

浏览器类命令默认只作用于当前选择。源列表里选中的是工作副本本身时，作用于整个工作副本。

受此规则约束的命令包括：提交、更新、还原、锁定、解锁、比较。

例外：

- 「提交全部更改」（`⌥⌘T`）始终作用于整个工作副本
- 移动产生的成对路径视为一个选择单位

菜单项的标题随选择变化，例如选中三个文件时显示「提交 3 个文件」，选中工作副本时显示「提交全部更改」。

按住 Option 会把当前菜单项换成它的替代项（已确认的例子）：

| 原项 | 按住 Option |
| --- | --- |
| 与 BASE 比较 | 用外部工具与 BASE 比较 |
| 与 HEAD 比较 | 用外部工具与 HEAD 比较 |
| 全选（比较视图，作用于左侧） | 全选右侧（`⌥⌘A`） |
| 提交列表里点文件夹复选框 | 递归勾选或取消 |

### 验收

- [ ] 同一命令在「选中工作副本」和「选中文件」下作用范围不同
- [ ] `⌥⌘T` 不受选择影响
- [ ] Option 能切出已确认的替代命令

## 20. 偏好设置

`⌘,`。下列各页都要有。

### 20.1 通用

- 双击工作副本文件：用编辑器打开 / 与 BASE 比较 / 快速查看
- 等宽字体、Tab 宽度、字体平滑
- 提交日志的字号
- 外部比较工具、外部合并工具
- 比较默认值：行内差异、行号、空白差异、换行差异、不可见字符、标注

### 20.2 工作副本

- 全局忽略列表，预置包含 `.DS_Store`
- 自动属性（`auto-props`）开关和规则表
- 使用提交时间作为文件修改时间（`use-commit-times`）
- 更新时显示记录
- 允许不写明修订的外部引用（关闭对应警告）
- 允许外部引用 URL 中含用户名（关闭对应警告）
- 默认的提交前脚本

### 20.3 安全

- SSL：查看和移除已信任的服务器证书；客户端证书及口令
- SSH：私钥、agent、是否在缺少指纹时询问、`SendEnv` 的默认值
- HTTP 代理：主机、端口、用户名、密码
- 密码策略：存入钥匙串 / 不保存

### 20.4 位置

- Subversion 配置：`~/.subversion`（默认）或 Mortar 私有目录
- SSH 配置与 `known_hosts`：`~/.ssh`（默认）或 Mortar 私有目录
- 说明文字写清：私有目录不会被其他 Subversion 客户端读取

提供这两项，是为了覆盖 Cornerstone 3 的 Locations 能力。默认选共享目录，因为 Mortar 不启用沙盒。

### 20.5 通知

每种长操作单独开关，默认全关。种类：检出、更新、提交、导入、导出。

开关打开时，操作结束发送「通知中心」通知。应用在前台时不额外弹 Dock 弹跳。

Dock 图标徽章显示未提交更改数量，使用系统千分位。徽章是否出现同时服从系统「通知」设置里对该应用的徽章开关。

### 20.6 用户属性

- 总开关「启用用户属性」。关闭后检查器不显示该段
- 列表：名称、检查器标签、类型（文本 / 复选框 / 弹出列表 / 文件）
- 弹出列表可编辑选项
- 名称限制：非空、不含空白，且不以 `svn:` 开头（`svn:` 留给内置属性）

### 验收

- [ ] 六个偏好页都存在，重启后设置仍在
- [ ] 全局忽略对导入和状态显示生效
- [ ] 位置页能在共享配置和私有配置之间切换
- [ ] 通知按操作种类开关；Dock 徽章是未提交数量

## 21. 认证、钥匙串与并发

- 需要认证时弹出一次对话框。失败后允许改用户名和密码再试。不要对同一次操作连续弹出多次相同对话框
- 选择保存时写入钥匙串项，按仓库 URL 和用户名区分
- 钥匙串里的密码错误时，提示更新，而不是无限重试
- 同一工作副本不支持多个 Mortar 窗口同时写。第二个写操作要等第一个结束
- 工作副本应位于本机磁盘或直接连接的外置磁盘。路径在网络卷上时给出警告，仍允许用户继续
